## الحل الواحد المقترح

مستودع عام مؤقت مستقل، اسمه المقترح فقط mstafa0932/pr49-coderabbit-review-20261022، لتشغيل مهمة يدوية واحدة على GitHub-hosted ubuntu-24.04 القياسي. لا Workflow في spot-scanner، ولا جدولة أو Scanner أو Controller جديد.

توثق GitHub أن Runner القياسي في المستودعات العامة مجاني، وأن الفئة الكاملة VM جديدة لكل مهمة، وأن Linux يتيح sudo دون كلمة مرور. لذلك يمكن مبدئيًا إعداد حدود العمليات والملفات والشبكة داخل VM منفصلة. هذه إمكانات موثقة وليست نتيجة اختبار البيئة المطلوبة. ubuntu-slim وLarger Runner وSelf-hosted مستبعدة.

### الصلاحيات والعزل المطلوب إثباتهما

- permissions: {} لتعطيل صلاحيات GITHUB_TOKEN؛ لا PAT أو OIDC أو GitHub App أو بيانات إنتاج أو checkout يحتفظ بالاعتماد. لا رمز GitHub داخل عملية CLI.
- CLI داخل حاوية بعمليات ومجلدات وشبكة منفصلة، مستخدم غير root، إسقاط capabilities، no-new-privileges، جذر وشيفرة للقراءة فقط، ومجلد مؤقت محدود للكتابة. لا host network/PID ولا mount لمجلد المضيف أو proc المضيف أو Docker socket.
- شبكة داخلية مع مسار خروج وحيد عبر proxy مراقب. يجب إضافة قواعد DOCKER-USER وINPUT المناسبة؛ Docker --internal وحده يسمح بالوصول إلى gateway وخدمات المضيف، ولا يكفي.
- قبل أي شيفرة أو اعتماد خدمة: اختبارات منع قراءة/كتابة مسارات المضيف ورؤية عملياته، ومنع الخروج المباشر وIPv6 وDNS غير المصرح وmetadata والشبكات الخاصة وخدمات المضيف. أي فشل يوقف المسار.
- تُحفظ اتصالات وكيل GitHub على المضيف منفصلة عن شبكة CLI؛ لا تُمنح الحاوية اتصال المضيف بحجة حاجة الـRunner إليه.
